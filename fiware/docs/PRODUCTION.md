# Production deployment (Coolify)

The ARISE middleware (Orion-LD with native DDS, TimescaleDB, Mintaka, Grafana, aura-monitor, WireCloud) runs on
**Coolify, server `server-2`, project `aura`, environment `production`**, from `docker-compose.prod.yml`. Public address:
**https://aura-dash.sensifai.com**.

```
Real Artaban robot  --DDS domain 0--> orion      -> mintaka      -> aura-monitor  -> WireCloud dashboard "Aura"
Simulator / tests   --DDS domain 1--> orion-sim  -> mintaka-sim  -> monitor-sim   -> WireCloud dashboard "Simulator"
```

Both dashboards are built from the same widgets (the 14 KPI, telemetry and alert widgets) and differ only in which broker
they read (`wirecloud/build.py` writes two mashups; the Simulator one overrides the broker, history and report
addresses). The two data planes never mix: each Orion-LD has its own Mongo database (`orion`, `orion_sim`) and its own
TimescaleDB database of the same name (checked locally: entities written to one broker appear only in its database),
and each Mintaka reads one database.

## Public surface

| What | Where | Notes |
| --- | --- | --- |
| WireCloud (both dashboards) | `https://aura-dash.sensifai.com` (Traefik, TLS) | login required; own admin account, no default `admin/admin` |
| Grafana | `https://aura-dash.sensifai.com/grafana/` | own login, anonymous access off |
| Mission report pages | `https://aura-dash.sensifai.com/monitor/aura/reports/<id>` and `/monitor/sim/...` | read only (GET); the monitors' APIs are **not** exposed |
| Live updates | `https://aura-dash.sensifai.com/eventsource` | ngsi-proxy, needed by the dashboards |
| DDS, real robot (domain 0) | UDP 7400, 7410-7419 on the server's address | robot sets `ROS_STATIC_PEERS` to it |
| DDS, Simulator (domain 1) | UDP 7650, 7660-7669 on the server's address | |

**Not published:** Orion-LD HTTP, Mintaka, Mongo, Postgres, the monitors (all internal; WireCloud's proxy reaches Orion-LD
and Mintaka server-side, so the browser never needs them).

**Firewall:** Coolify publishes the DDS ports on the host but cannot open the host or cloud firewall. Open the UDP ports
above there, and **restrict them to the robot's address** (DDS has no authentication: anyone who can reach the port can
write telemetry). `aura-dash.sensifai.com` is behind Cloudflare's proxy, which carries HTTPS only: robots must use the
server's IP address (or a DNS-only name) for DDS, never the proxied name. Robot side: [DDS_INTEGRATION.md](DDS_INTEGRATION.md).

## Secrets

Generated by Coolify and stored as environment variables of the application (nothing is in Git):

| Variable | Used for |
| --- | --- |
| `SERVICE_PASSWORD_POSTGRES` | TimescaleDB, Orion-LD TROE, Mintaka, monitors, Grafana datasource |
| `SERVICE_PASSWORD_WIRECLOUD` | WireCloud admin password |
| `SERVICE_PASSWORD_GRAFANA` | Grafana admin password |
| `SERVICE_PASSWORD_64_WIRECLOUDKEY` | Django `SECRET_KEY` (the image's built-in key is public) |
| `ARISE_ADMIN_USER` (default `arise-admin`) | WireCloud and Grafana admin user name |

The WireCloud admin account follows the environment on every deploy (`wirecloud/init.prod.sh` re-applies the password
and deletes a default `admin` user if one exists). To rotate a password: change the variable in Coolify and redeploy.
Retrieve the values in Coolify: application, Environment Variables.

## Deploying and updating

The application is a Docker Compose application from this repository (`fiware/docker-compose.prod.yml`), built from
Git by Coolify through the `sensifai-bot` GitHub app. Orion-LD downloads the NGSI-LD core `@context` from
`uri.etsi.org` at runtime, so the server needs outbound internet access.

- **Configuration is baked into images** (`deploy/*.Dockerfile`: Orion-LD DDS mapping, nginx routes, Grafana provisioning
  and dashboards, the WireCloud init sources). Coolify does not copy repository files for relative bind mounts of a Git
  compose application, it creates empty folders instead, so the compose file uses no bind mounts and a config change
  needs a redeploy (rebuild).
- **Performance:** WireCloud serves widget files from `/showcase/media/<vendor>/<widget>/<version>/...` without any cache
  headers, so each dashboard load re-downloaded the files of all 14 widgets. nginx now caches them (7 days, keyed by the
  versioned URL) and adds `Cache-Control` so the browser and Cloudflare can keep them too; a changed widget therefore
  has to ship as a new version, never under the same one. The remaining cost is one API round trip per widget, which
  depends on the visitor's network path (a VPN that routes the browser through the server itself adds a hairpin).
- **Widget change:** edit the widget, bump `VERSION` in `wirecloud/build.py`, `version=` in
  `wirecloud/operators/ngsild-source/config.xml` and `AURA_VERSION` in both compose files, redeploy with
  `AURA_RECREATE_WORKSPACE=1` once to rebuild the two dashboards from the new mashups.
- **Topic change:** edit `orion/config-dds.json` and `orion/config-dds-sim.json` together, redeploy.
- **WireCloud data** (SQLite on a volume) and the Mongo / Timescale / Grafana volumes hold the state: back them up.

## Checking the deployment against the ARISE documentation (D2.1)

| ARISE D2.1 requirement | In this deployment |
| --- | --- |
| Orion-LD with native Fast DDS, Phase I "legacy mode", DDS topics mapped to entities by a config file | `fiware/orion-ld:1.10.0` (D2.1 baseline: 1.7.0), `-wip dds`, `orion/config-dds*.json` with `dds` and `ngsild.topics` |
| Non-intrusive: no change to the running DDS system | robots publish standard ROS 2 topics; only the allow-list is read |
| Every DDS sample is one NGSI-LD attribute; topic to entity id, type and attribute from the file | each mapped topic has an entry (see the table in DDS_INTEGRATION.md) |
| Read mode (DDS to NGSI-LD) | in use; verified end to end |
| Write mode (NGSI-LD to DDS), expected January 2025 | mapping is bidirectional; not exercised here |
| NGSI-LD API for queries and subscriptions | Orion-LD API (internal) plus subscriptions used by aura-monitor and the dashboards |
| Temporal representation | TROE into TimescaleDB, served by Mintaka |
| Phase II "NGSI-LD aware" mode (topic names are NGSI-LD attributes, no config file) | not used; D2.1 schedules it for the second release |

D2.1 says nothing about ports, authentication or deployment hardening, so those choices (published ports, secrets,
internal-only HTTP) follow Fast DDS defaults and normal practice rather than a requirement of the document.
